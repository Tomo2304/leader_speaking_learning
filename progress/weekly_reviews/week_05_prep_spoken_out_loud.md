# Week 5 — PREP Spoken Out Loud
*Phase 2: Spontaneous Speaking | 2026-06-08 to 2026-06-12*

## Key Topic
Taking PREP from written practice to spoken delivery — using it live in real time with a 10-second pause to structure your response before speaking.

## Key Concepts Covered
- The 10-second pause: silence before responding is not weakness, it is structure
- Spoken PREP vs written PREP — what changes when you say it out loud
- Pre-preparing PREP responses for meetings where your opinion is likely to be asked

## Examples from Practice

| # | Your original | Improved version | What changed |
|---|---|---|---|
| 1 | "We must assess how AI use cases have been captured in JPD. We need to help enterprise prioritising use cases therefore, we need to familialise ourselves with use cases and identify any lacking information. Without them, we will not be able to liaise with business to collect all required info to progress use cases and help prioritising other use cases. These learnings will become invaluable for establishing AI use cases opportunity assessment frameworks, therefore we need to start learning current use cases." | **P:** Our first step needs to be reviewing how AI use cases are currently captured in JPD. **R:** We can't help the enterprise prioritise them until we understand each use case and spot where information is missing. **E:** Without that baseline, we can't go back to the business to gather the details each use case needs to progress. **P:** So if we start learning the current use cases now, we'll have what we need to build a proper opportunity-assessment framework later. | Led with conclusion and closed on action (good). Fixes: split the breathless "therefore… without them… therefore" chain into four distinct beats you can pause between; crisper one-sentence Point; "help prioritising" → "help prioritise"; "familialise" → "familiarise". |
| 2 | *Question being prepped: "Why do we need to present a Signal progress update to senior leaders (AET)?"* "We must present a progress update to AET for the signal project. AETs would like a detailed update on how this project is moving and assurance on how we progressed projects with sales led in our mind. Signals had a significant challenge in other region especially UK as they created way too many signals for sales and sales stopped paying attention to them. Therefore, we need to ensure delivering only signals to the sales that they see value actioning." | **P:** We need to take this to AET to give them assurance the Signal project is being run sales-led — so it actually gets used, not ignored. **R:** Their real concern is adoption, and the credible way to address it is to show we've designed deliberately against the failure that hit other regions. **E:** In the UK, the team pushed out so many signals that sales stopped paying attention entirely — the volume killed the value. **P:** So the purpose of this update isn't just to report status — it's to assure AET we're only delivering signals sales see value in actioning, so we don't repeat the UK outcome. | Original opening was the task ("we must present an update"), not an answer to *why*. Reframed the Point to justify the meeting's purpose (assurance on a sales-led approach); kept the UK case as the Example proving the assurance is warranted. Fixes: "in other region" → "other regions"; "value actioning" → "value in actioning". |
